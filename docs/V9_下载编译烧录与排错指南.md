# TPMS Project V9 下载、编译、烧录与排错指南

本文档适用于版本：

```text
v9_snTPMS_learning_ffb2
```

对应仓库：

```text
https://github.com/yinwuhui-art/TPMS_Project
```

V9 的主要功能如下：

- 使用广播名称 `snTPMS` 和四个完整 MAC 地址进行双重筛选。
- 解析新的 10 字节 Manufacturer Data。
- 将传感器 ID、压力、温度、Info 和 FunctionReuse 上报到 FFB2。
- 自学习顺序为 LF、RF、RR、LR。
- 学到新轮胎后保留之前已经学习成功的 position 位。

## 1. 下载 V9 源码

### 1.1 使用 Git 下载

```bash
git clone https://github.com/yinwuhui-art/TPMS_Project.git
cd TPMS_Project
git checkout v9_snTPMS_learning_ffb2
```

执行下面的命令确认当前版本：

```bash
git describe --tags --always
```

预期应显示：

```text
v9_snTPMS_learning_ffb2
```

### 1.2 下载 ZIP

进入下面的版本页面：

```text
https://github.com/yinwuhui-art/TPMS_Project/tree/v9_snTPMS_learning_ffb2
```

点击 `Code -> Download ZIP`，下载后完整解压。不要直接在 ZIP 压缩包内部打开 CCS 工程。

## 2. 推荐开发环境

为了减少工具版本差异造成的问题，建议使用以下环境：

| 项目 | 推荐版本 |
| --- | --- |
| Code Composer Studio | CCS 12.8.1 |
| SimpleLink Low Power F3 SDK | 9.20.00.81 |
| SysConfig | 1.26.3 |
| TI ARM Clang | 3.2.2 LTS |
| 芯片 | CC2745R10-Q1 |
| 开发板 | LP_EM_CC2745R10_Q1 |
| 调试器 | TI XDS110 |
| RTOS | FreeRTOS |

SDK 推荐安装路径：

```text
C:\ti\simplelink_lowpower_f3_sdk_9_20_00_81
```

工程的 `basic_ble.syscfg` 明确使用：

```text
simplelink_lowpower_f3_sdk@9.20.00.81
```

如果 CCS 没有识别 SDK，请在 CCS 中打开：

```text
Window
-> Preferences
-> Code Composer Studio
-> Products
```

添加 SDK 安装目录并重新启动 CCS。

## 3. 在 CCS 中导入工程

1. 启动 CCS。
2. 点击 `File -> Import`。
3. 选择 `Code Composer Studio -> CCS Projects`。
4. 在搜索目录中选择解压后的 `TPMS_Project` 根目录。
5. 选择工程：

   ```text
   basic_ble_LP_EM_CC2745R10_Q1_kuangjia
   ```

6. 点击 `Finish`。
7. 右键工程，打开 `Build Configurations -> Set Active -> Release`。
8. 右键工程，执行 `Clean Project`。
9. 执行 `Build Project`。

第一次导入时，应让 CCS 重新生成 Debug 或 Release 构建文件。不要直接使用另一台电脑生成的 makefile。

## 4. 工程绝对路径问题

这是换电脑后最容易出现的问题。

工程配置或者 CCS 自动生成的 makefile 中，可能保存开发电脑上的路径，例如：

```text
D:\CCS_Item\basic_ble_LP_EM_CC2745R10_Q1_kuangjia
D:\CCS_Item\GMW TPMS BLE-1.2\...
C:\ti\simplelink_lowpower_f3_sdk_9_20_00_81
D:\ti\ccs1281\...
```

这些路径在其他电脑上不一定存在。

### 4.1 头文件找不到

可能出现：

```text
fatal error: 'xxx.h' file not found
```

处理步骤：

1. 右键工程，进入 `Properties`。
2. 打开：

   ```text
   Build
   -> Arm Compiler
   -> Include Options
   ```

3. 删除已经失效的外部绝对路径。
4. 使用 CCS 的 Workspace 或 File system 按钮，重新添加本工程目录：

   ```text
   app
   app/tpms
   app/tpms/ble
   app/tpms/core
   app/tpms/phone
   app/tpms/sensor
   app/tpms/storage
   app/tpms/diag
   common
   common/Profiles/simple_gatt
   ```

5. 确认 SDK 的 include 路径来自 CCS Product 变量，而不是原电脑的 SDK 绝对路径。
6. 再次执行 `Clean Project` 和 `Build Project`。

### 4.2 编译器路径错误

可能出现：

```text
tiarmclang.exe not found
```

进入：

```text
Project Properties
-> General
-> Compiler version
```

选择本机已经安装的 `TI ARM Clang 3.2.2 LTS`。

如果列表中没有该编译器，请先在 CCS 安装对应版本，或者让 CCS 自动发现其安装目录。

### 4.3 SysConfig 路径或产品错误

可能出现：

```text
sysconfig_cli.bat not found
product.json not found
product not installed
```

检查：

```text
Project Properties
-> General
-> Products
```

确保选择：

```text
SimpleLink Low Power F3 SDK 9.20.00.81
SysConfig 1.26.3
```

不要手动执行 `Debug/subdir_rules.mk` 或 `Release/subdir_rules.mk` 中保存的旧 SysConfig 命令。

## 5. 推荐构建方法

推荐从 CCS 界面构建：

```text
Project -> Clean
Project -> Build Project
```

不推荐直接进入 `Debug` 或 `Release` 目录运行：

```bash
make
gmake
```

原因是这些目录中的文件由 CCS 自动生成，可能包含生成它们的电脑上的绝对路径。

正常构建完成后，一般会生成：

```text
Release/basic_ble_LP_EM_CC2745R10_Q1_kuangjia.out
Release/basic_ble_LP_EM_CC2745R10_Q1_kuangjia.hex
```

这些编译输出默认不会提交到 Git。

## 6. 下载和调试

工程提供的目标配置为：

```text
targetConfigs/CC2745R10.ccxml
```

该配置使用：

```text
Texas Instruments XDS110 USB Debug Probe
CC2745R10
```

操作步骤：

1. 使用 USB 连接 XDS110。
2. 确认 CC2745R10-Q1 板卡供电正常。
3. 在 CCS 中选中工程。
4. 点击 `Debug`。
5. CCS 完成连接和程序下载后，点击 `Resume`。

如果提示无法连接目标：

- 检查开发板供电。
- 检查 XDS110 USB 驱动。
- 检查调试排线方向。
- 确认目标配置选择的是 CC2745R10。
- 在 Target Configuration 中执行 `Test Connection`。
- 关闭其他正在占用 XDS110 的 CCS、UniFlash 或调试程序。

## 7. V9 自学习测试流程

### 7.1 手机端操作

1. 扫描并连接 BLEM。
2. 订阅 FFB2 的 Notify。
3. 向 FFB1 写入开始学习命令：

   ```text
   02
   ```

4. 按下面顺序用低频工具触发传感器：

   ```text
   LF 左前
   RF 右前
   RR 右后
   LR 左后
   ```

5. 每学完一个轮位，等待 App 显示学习完成后再移动到下一个位置。

### 7.2 position 预期结果

FFB2 Byte11 为累计轮位标志：

| 学习进度 | Byte11 |
| --- | --- |
| LF | `0x01` |
| LF + RF | `0x03` |
| LF + RF + RR | `0x0B` |
| LF + RF + RR + LR | `0x0F` |

新轮胎学习成功时，之前已经学习成功的 position 位不会被清除。

## 8. 新传感器广播格式

Manufacturer Data 长度至少为 10 字节：

| 索引 | 字段 | FFB2 对应位置 |
| --- | --- | --- |
| 0～3 | Sensor ID | Byte2～Byte5 |
| 4 | Pressure | Byte6 |
| 5 | Temperature | Byte7 |
| 6 | Info | Byte8 |
| 7～8 | FunctionReuse | Byte9～Byte10 |
| 9 | CRC8 | 不进入 FFB2 |

FFB2 固定为 12 字节：

| FFB2 字节 | 内容 |
| --- | --- |
| Byte0～Byte1 | 固定值 `00 01` |
| Byte2～Byte5 | Sensor ID |
| Byte6 | Pressure |
| Byte7 | Temperature |
| Byte8 | Info |
| Byte9～Byte10 | FunctionReuse |
| Byte11 | 累计 position |

## 9. V9 传感器筛选条件

传感器必须同时满足以下条件：

1. Local Name 严格等于：

   ```text
   snTPMS
   ```

   名称区分大小写。

2. 完整 MAC 地址命中白名单。
3. Manufacturer Data 长度不少于 10 字节。
4. FunctionReuse1 的 bit1 为 1，才会进入学习流程。
5. 同一个物理传感器不能在同一轮学习中重复使用。

名称可能位于 Scan Response，Manufacturer Data 可能位于普通 Advertising Data。程序会按完整 MAC 记住已经通过名称验证的传感器。

## 10. 当前 MAC 白名单

白名单配置文件：

```text
app/tpms/tpms_config.h
```

当前配置：

```text
D0:39:3F:18:90:44
D0:39:3F:19:92:64
D0:39:3F:19:97:96
D0:39:3F:1B:CC:45
```

其中第一只传感器的 MAC 是根据手写图片识别为：

```text
D0:39:3F:18:90:44
```

正式使用前请再次确认 `90` 是否正确。

更换传感器后，必须同时检查：

- 广播名称。
- 完整 MAC 地址。
- Manufacturer Data 长度和字段顺序。
- FunctionReuse 低频触发位。
- Sensor ID 是否仍位于 Manufacturer Data 的前4字节。

## 11. 常见运行问题

### 11.1 能扫描到传感器但不能学习

依次检查：

- 名称是否严格为 `snTPMS`。
- MAC 是否在四个白名单中。
- 手机显示的 MAC 和 TI BLE Stack 回调顺序是否相反。
- Manufacturer Data 是否为10字节。
- FunctionReuse1 bit1 是否为1。
- 是否已经向 FFB1 写入 `02`。
- 当前传感器是否已经在本轮学习过。

### 11.2 App 收不到 FFB2

检查：

- 手机是否已经订阅 FFB2 Notify。
- 手机与 BLEM 是否仍保持连接。
- App 是否先发送了开始学习命令。
- 是否确实触发了符合条件的低频帧。
- FFB2 CCCD 是否已开启。

### 11.3 position 不符合预期

必须按照下面的顺序触发：

```text
LF -> RF -> RR -> LR
```

程序按照学习步骤分配轮位，不是单纯按照 MAC 自动决定轮位。

### 11.4 修改代码后仍运行旧程序

执行：

```text
Clean Project
Build Project
Debug
```

确认下载的是刚生成的 `.out`，并在下载完成后点击 `Resume`。

## 12. Git 使用注意事项

`Debug`、`Release`、`.out`、`.hex`、`.map` 等属于构建输出，不应作为源代码修改提交。

提交代码前建议执行：

```bash
git status
git diff
```

如果只是 CCS 自动生成文件发生变化，应先确认这些文件是否真的需要纳入版本。

开发新功能时建议从 V9 创建新分支：

```bash
git checkout -b feature/功能名称 v9_snTPMS_learning_ffb2
```

完成并验证后再合并到主分支。
